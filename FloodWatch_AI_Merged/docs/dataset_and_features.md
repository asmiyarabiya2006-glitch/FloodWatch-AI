# Dataset and Feature Documentation — FloodWatch AI

## Development smoke-test dataset
`ml/demo_flood_dataset.csv` is generated synthetic data used only to confirm that the pipeline, training script, metrics, model serialization, and prediction function execute correctly. It is not collected environmental data and must not be cited as real-world observations or used to claim real flood prediction performance.

## Recommended public-data direction
For the final evaluation, use a documented dataset whose provenance and labels can be checked. A candidate public repository for Indian flood-risk experiments is:
- Khyathi-Priya, Flood-Risk-detection-in-India: https://github.com/Khyathi-Priya/Flood-Risk-detection-in-India

Inspect its README, CSV schema, target construction, license, and whether labels are observed or simulated before using it. Do not assume that a public GitHub repository means its rows are observed real-world measurements. If the source labels or feature values are synthetic, describe the study as a synthetic-data experiment.

An alternative research dataset from Zenodo describes observational flood-event patches with precipitation and ground-truth inundation labels, but it is large and image/segmentation-oriented rather than a ready-made tabular CSV:
https://zenodo.org/records/23470601

## Feature definitions in the bundled demo only
- `Rainfall_mm`: synthetic rainfall amount in millimetres.
- `RiverLevel_m`: synthetic river level in metres.
- `Temperature_C`: synthetic temperature in Celsius.
- `Humidity_pct`: synthetic relative humidity percentage.
- `SoilMoisture_pct`: synthetic soil moisture percentage.
- `DrainageIndex`: synthetic index from 0 to 100; semantics are illustrative.
- `Elevation_m`: synthetic elevation in metres.
- `FloodRisk`: synthetic class label generated by a formula for software testing.

These feature values and labels are illustrative only. They are not an official hydrological rule.

## Target handling
- If your dataset already has `Low`, `Moderate`, `High` risk labels, the code standardizes them.
- If it has a binary numeric flood label, the lower value maps to Low Risk and the higher value to High Risk. Confirm this matches the dataset definition.
- If the target is a continuous numeric score with more than 10 distinct values, the default demo bins are `<0.35` Low, `0.35–<0.65` Moderate, and `>=0.65` High. These are configurable and are not universal flood thresholds. Use the data dictionary or a justified thresholding method for final work.
- If the dataset uses different labels, check the mapping and document it before presenting results.

## Avoiding leakage
The preprocessing pipeline learns imputation and categorical encoding only from training data. Test data is held out until evaluation. If the dataset contains repeated locations over time, split by time or location for a more realistic final evaluation rather than relying solely on a random split.
